Ejercicio: Ejecutar MongoDB con Docker

Descargar la imagen

docker pull mongo:4.4.6

Ejecutar el contenedor

docker run -p 27017:27017 \
  -e MONGO_INITDB_ROOT_USERNAME=root \
  -e MONGO_INITDB_ROOT_PASSWORD=root \
  --name my-mongo mongo:4.4.6

Acceder al contenedor

docker ps
docker exec -ti my-mongo bash

Iniciar el cliente

mongo --username root --password root \
  --authenticationDatabase admin

show dbs

Comandos

Seleccionar base

use hotels

Consultar documentos

db.hotels.find().pretty()
db.hotels.find({ name: "Grand Hotel" }).pretty()

Crear colección e insertar documentos

db.hotels.insertMany([
  {
    id: 1,
    name: "Grand Hotel",
    city: "Springfield",
    state: "IL",
    country: "USA",
    rating: 4.5,
    available_rooms: 20,
    price_per_night: 150.00,
    amenities: ["Free WiFi", "Pool", "Gym"]
  },
  {
    id: 2,
    name: "Cozy Inn",
    city: "Oakville",
    state: "CA",
    country: "USA",
    rating: 3.8,
    available_rooms: 15,
    price_per_night: 90.00,
    amenities: ["Free Breakfast", "Parking"]
  }
])

Comandos

Modificar documentos

db.hotels.updateOne(
  { name: "Grand Hotel" },
  { $set: { address: "999 Washington St" } }
)

Eliminar documentos

db.hotels.deleteOne({ name: "Grand Hotel" })
db.hotels.deleteMany({ rating: { $lt: 3 } })

Contar documentos

db.hotels.countDocuments({})

Ordenar y limitar

db.hotels.find().sort({ rating: 1 }).pretty()
db.hotels.find().limit(2).pretty()

Saltar resultados

db.hotels.find().skip(2).pretty()

Eliminar colección y salir

db.hotels.drop()
exit

Bloque 2

Implementación en Go con interfaces

Lo hacemos así para separar responsabilidades.

  • La app real usa MongoDB.
  • Los tests pueden usar un mock en memoria.
  • La interfaz permite cambiar una implementación por otra sin romper el resto.

¿Qué es una interfaz?

Definición simple

Una interfaz es un contrato: dice qué se puede hacer, pero no obliga a usar una sola implementación.

HotelsRepo GetHotelByID(id)
↓
MongoDB app real
Mock tests

1. Definir la interfaz

type HotelsRepo interface {
  GetHotelByID(id int64) (HotelDAO, error)
}
↓

Idea principal

La interfaz debe ser genérica.

2. Implementar la interfaz MongoDB

type HotelsRepo interface {
  GetHotelByID(id int64) (HotelDAO, error)
}

type HotelsMongoDB struct{}

func (repo HotelsMongoDB) GetHotelByID(id int64) error {
}
↓

Implementación real

Se usará durante la ejecución de la aplicación.

3. Implementar la interfaz Mock

type HotelsRepo interface {
  GetHotelByID(id int64) (HotelDAO, error)
}

type HotelsMongoDB struct{}
func (repo HotelsMongoDB) GetHotelByID(id int64) error {
}

type HotelsMock struct{}
func (repo HotelsMock) GetHotelByID(id int64) error {
}
↓

Implementación mock

Sirve para tests y desarrollo desacoplado.

4. Separar implementaciones

type HotelsRepo interface {
  GetHotelByID(id int64) (HotelDAO, error)
}

type HotelsMongoDB struct {
  client *mongo.Client
}

func (repo HotelsMongoDB) GetHotelByID(id int64) error {
  repo.client.Database("hotel-platform").
    Collection("hotels").
    Find(ctx, bson.M{"id": id})
}
↓

Implementación real

Conecta contra MongoDB y consulta la colección real.

4. Separar implementaciones

type HotelsRepo interface {
  GetHotelByID(id int64) (HotelDAO, error)
}

type HotelsMongoDB struct {
  client *mongo.Client
}

func (repo HotelsMongoDB) GetHotelByID(id int64) error {
  repo.client.Database("hotel-platform").
    Collection("hotels").
    Find(ctx, bson.M{"id": id})
}

type HotelsMock struct {
  docs map[string]HotelDAO
}

func (repo HotelsMock) GetHotelByID(id int64) error {
  return docs[id]
}
↓

Implementación mock

Usa datos en memoria para responder durante los tests.

5. Sugerencia de organización de archivos

DAOs

hotels-api/
  dao/
    hotels/
      hotels_dao.go

Un paquete para definir los DAOs.

Repositorios

hotels-api/
  repositories/
    hotels/
      hotels_mock.go
      hotels_mongo.go

Un paquete para definir los repositorios.

Servicio

hotels-api/
  services/
    hotels/
      hotels_service.go

El servicio usa el repositorio MongoDB.

Tests

hotels-api/
  services/
    hotels/
      hotels_service_test.go

Los test del servicio usan el repositorio Mock.
