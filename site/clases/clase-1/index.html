Parte 1 · Teoría

¿Qué es la Arquitectura de Software?

La arquitectura define cómo se organiza un sistema. Su calidad, mantenibilidad y escalabilidad dependen de esa estructura.

Cuando el proyecto crece, la arquitectura deja de ser un detalle.

Parte 1 · Teoría

Arquitectura Monolítica

Toda la lógica de UI, negocio y datos empaquetada en un único despliegue.

Single-process

Todo el código corre en un solo proceso ejecutable.

Monolito modular

Módulos internos separados, pero desplegados juntos.

Monolito distribuido

Servicios separados con tanto acoplamiento que obligan a desplegar todo junto.

Parte 1 · Teoría

Arquitectura de Microservicios

Servicios pequeños, independientes y poco acoplados, con despliegue autónomo.

Escalabilidad independiente

Cada servicio escala según su propia demanda.

Mantenibilidad

Actualizar partes chicas suele ser más manejable.

Flexibilidad

Permite elegir herramientas distintas según el problema.

Concurrencia

Procesamiento simultáneo de requests sin bloquear todo el sistema.

Parte 2 · Práctica

Los 3 problemas críticos del monolito

Acoplamiento alto

Un error en un módulo puede romper funcionalidades no relacionadas.

Escalabilidad limitada

No se puede escalar solo la tienda o las reservas sin escalar todo.

Despliegues riesgosos

Cada deploy toca el sistema completo y eleva el riesgo operativo.

Primera Decisión

Migrar hacia microservicios

Objetivo: lograr bajo acoplamiento y alta cohesión.

Parte 2 · Teoría

Microservicios con Interfaces y Mocks

El microservicio de Actividades necesita validar con Usuarios si una persona tiene la cuota al día antes de reservar una clase.

Problema: si Usuarios no está listo o no responde, Actividades queda bloqueado.

La solución

Interfaces y Mocks

1

Contrato

Definir una interface compartida para la respuesta esperada.

2

Mock

Usar una implementación fake para desarrollar sin esperar al otro equipo.

3

Real

Reemplazar luego el mock por la llamada HTTP real sin cambiar el resto del código.

Ventaja: los equipos trabajan en paralelo; el acuerdo es el contrato, no la implementación.
